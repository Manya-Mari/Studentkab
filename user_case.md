# USER CASE — Личный кабинет успеваемости студента

## 1. Назначение

Документ описывает пользовательские сценарии, ожидаемое поведение
приложения и критерии приёмки.

**Пользователь:** студент, который хочет вести журнал оценок и
отслеживать успеваемость.

## 2. Сущности

**Discipline:** `id`, `name`, `teacherName` (необязательно).

**Grade:** `id`, `disciplineId`, `value`, `date`, `workType`, `comment`.

Одна дисциплина может иметь несколько оценок; каждая оценка относится к
одной дисциплине.

## 4. Пользовательские сценарии

### UC-01. Просмотр общей сводки

**Как студент, я хочу** видеть общую сводку, чтобы быстро понимать
состояние успеваемости.

1. Студент открывает приложение.
2. Система показывает общий средний балл, количество оценок и краткую
   сводку по дисциплинам.

**Альтернатива:** если оценок нет, система показывает пустое состояние.

**Критерии приёмки:** значения соответствуют сохранённым данным; при
отсутствии оценок не возникает деления на ноль.

**Статус Спринт 2:** данные о дисциплинах и оценках сохраняются и
читаются из Room; средний балл будет рассчитываться в Спринте 4.

### UC-02. Просмотр списка дисциплин

**Как студент, я хочу** видеть дисциплины и средний балл по каждой.

1. Студент открывает список дисциплин.
2. Система показывает названия и средние баллы.
3. Студент выбирает дисциплину.

**Альтернатива:** при отсутствии дисциплин отображается понятное
сообщение.

**Критерии приёмки:** отображаются все сохранённые дисциплины; средние
баллы рассчитаны по оценкам соответствующего предмета; для дисциплины
без оценок не показывается ложное числовое значение.

**Статус Спринт 2:** слой данных поддерживает получение всех дисциплин и
их оценок; UI — Спринт 3.

### UC-03. Просмотр журнала дисциплины

**Как студент, я хочу** видеть оценки по выбранной дисциплине.

1. Студент выбирает дисциплину.
2. Система открывает журнал.
3. Для каждой записи показывает значение, дату, тип работы и
   комментарий, если он есть.

**Критерии приёмки:** отображаются только оценки выбранной дисциплины;
пустой журнал сопровождается сообщением.

**Статус Спринт 2:** DAO позволяет получить оценки по `disciplineId`;
подтверждено на тестовых данных; UI — Спринт 3.

### UC-04. Добавление оценки

**Как студент, я хочу** добавить оценку, чтобы вести актуальный журнал.

1. Студент открывает дисциплину и форму добавления.
2. Указывает дисциплину, значение, дату и тип работы.
3. При необходимости вводит комментарий.
4. Подтверждает сохранение.
5. Система проверяет данные, сохраняет запись и обновляет расчёты.

**Альтернативы:** незаполненное обязательное поле или оценка вне
диапазона 2–5 приводят к сообщению об ошибке; некорректные данные не
сохраняются.

**Критерии приёмки:** диапазон 2–5 включительно; новая запись
появляется в журнале; средний балл пересчитывается.

**Статус Спринт 2:** операция создания оценки в Room реализована и
проверена; валидация диапазона 2–5 работает на уровне слоя данных
(включая отказ для дробных значений); UI-форма — Спринт 3.

### UC-05. Редактирование оценки

**Как студент, я хочу** исправить оценку, если внёс её неверно.

1. Студент выбирает запись и открывает редактирование.
2. Изменяет поля и сохраняет.
3. Система проверяет данные и обновляет запись и средний балл.

**Критерии приёмки:** изменяется именно выбранная запись; проверка
диапазона действует; после сохранения данные и расчёты обновлены.

**Статус Спринт 2:** операция обновления оценки реализована и проверена;
изменения сохраняются после перезапуска; UI — Спринт 3.

### UC-06. Удаление оценки

**Как студент, я хочу** удалить ненужную или ошибочную запись.

1. Студент выбирает оценку и действие удаления.
2. Подтверждает действие, если подтверждение предусмотрено.
3. Система удаляет запись и пересчитывает средний балл.

**Критерии приёмки:** удаляется выбранная запись; список и средний балл
обновляются; при отсутствии оставшихся оценок показывается пустое
состояние.

**Статус Спринт 2:** операция удаления оценки реализована и проверена;
удаление дисциплины обрабатывает связанные оценки согласованным образом;
UI — Спринт 3.

### UC-07. Фильтрация и сортировка

**Как студент, я хочу** фильтровать и сортировать журнал, чтобы находить
нужные оценки.

1. Студент открывает журнал.
2. Выбирает фильтр по дисциплине, периоду или типу работы.
3. При необходимости сортирует по дате или значению.

**Критерии приёмки:** фильтры показывают только подходящие записи;
сортировка выполняется по выбранному полю; сброс фильтров возвращает
полный список.

**Статус Спринт 2:** запланировано на Спринт 4. Слой данных готов
предоставить необходимые выборки.

### UC-08. Просмотр динамики

**Как студент, я хочу** видеть изменение среднего балла по периодам.

1. Студент открывает раздел динамики.
2. Выбирает доступный разрез просмотра.
3. Система показывает изменение среднего балла в графическом или
   табличном виде.

**Критерии приёмки:** данные соответствуют оценкам; периоды упорядочены;
при недостатке данных отображается объяснение.

**Статус Спринт 2:** запланировано на Спринт 4. Даты оценок сохраняются
в Room, что обеспечивает основу для построения динамики.

### UC-09. Расчёт целевого среднего балла

**Как студент, я хочу** узнать, какая следующая оценка нужна для
достижения цели.

1. Студент открывает калькулятор и вводит целевой средний балл.
2. Система использует количество и сумму текущих оценок.
3. Рассчитывает требуемую следующую оценку и показывает результат.

Формула:

`Требуемая оценка = Целевой средний балл × (Количество текущих оценок + 1) − Сумма текущих оценок`

**Альтернатива:** если результат ниже 2 или выше 5, система сообщает,
что цель недостижима одной оценкой.

**Критерии приёмки:** расчёт соответствует формуле; используются оценки
выбранной дисциплины; недостижимый результат не выдаётся за допустимую
оценку.

**Статус Спринт 2:** запланировано на Спринт 5. Слой данных предоставляет
количество и сумму оценок по дисциплине.

## 5. Общие правила

1. Диапазон оценок — от 2 до 5 включительно.
2. В базовой версии все оценки имеют одинаковый вес.
3. Средний балл рассчитывается как среднее арифметическое.
4. При отсутствии оценок деление на ноль не выполняется.
5. Общий средний балл — среднее арифметическое по всем внесённым
   оценкам.
6. Формат и округление среднего балла должны быть единообразными.
7. Удаление дисциплины должно либо удалять связанные оценки, либо
   запрещаться с понятным предупреждением.

| Приоритет      | Функции                                                                 |
|----------------|-------------------------------------------------------------------------|
| Высокий        | Сводка, дисциплины, журнал, CRUD оценок, средние баллы, валидация и пустые состояния |
| Средний        | Фильтры, сортировка, динамика                                           |
| Дополнительный | Калькулятор целевого балла, подсветка низкой успеваемости               |

## 7. Критерий готовности

Сценарий принимается, если поведение реализовано, данные корректны,
альтернативные ситуации обработаны, а проверки подтверждают соответствие
критериям приёмки.

## 8. Результаты Спринта 2, влияющие на сценарии

- Модель данных `Discipline` и `Grade` реализована и соответствует
  паспорту приложения.
- Связь «1 дисциплина — N оценок» работает через `disciplineId`.
- CRUD по обеим сущностям проверен.
- Сохранение данных после перезапуска подтверждено.
- Закрыты дефекты:
    - BUG-01: средний балл отображался как 0 вместо «—» (исправлен);
    - BUG-02: валидация 2–5 не срабатывала для дробных значений
      (исправлен).
- Требования к UI-сценариям UC-01…UC-06 остаются в силе; их реализация
  переносится на Спринт 3.
